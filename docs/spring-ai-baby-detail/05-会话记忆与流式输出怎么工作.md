## 本章目标

这一章会把你最容易绕晕的部分讲细：

- 为什么 session 不是只有一个字符串
- 为什么 memory service 要这么多方法

## 一、先看 `AiConversationMemoryProperties`

这个类不是业务逻辑类。

它只是配置承载类。

里面这些字段你要一个个看懂：

### `maxTurns`

prompt memory 最多保留多少轮。

注意，是给模型看的短期记忆。

### `archiveMaxTurns`

归档历史最多保留多少轮。

注意，是给前端恢复历史看的。

### `recentTurnsForPrompt`

真正拼 prompt 时，最近几轮取多少。

### `summaryMaxChars`

摘要最长多少字符。

### `ttlHours`

这些会话数据在 Redis 里活多久。

## 二、先看 `AiConversationMemoryService`

这个类字段不多，但方法很多。

因为它管的是一个完整会话系统。

### 字段 1：`StringRedisTemplate`

说明会话数据是存在 Redis 里的。

### 字段 2：`ObjectMapper`

说明会话消息和 meta 需要序列化/反序列化。

### 字段 3：`AiConversationMemoryProperties`

说明很多行为是配置驱动的，而不是写死。

## 三、最重要的方法逐个看

### `ensureSessionId(...)`

作用：

如果前端传了 sessionId，就用它。  
如果没传，就生成一个新的。

这是新旧会话的分界点。

### `getPromptContext(...)`

作用：

取出这轮给模型看的上下文。

它返回的不是整个历史，而是：

- `summary`
- `recentTurns`

### `appendTurn(...)`

这是会话系统最关键的方法之一。

它不是“简单保存一条消息”。

它会同时更新：

- prompt-turns
- archive-turns
- scene
- summary
- session meta
- session index

你可以把它理解成：

`一轮对话结束后的统一写回操作。`

### `listSessions(...)`

作用：

给前端列出当前用户最近有哪些 session。

### `getSessionDetail(...)`

作用：

给前端恢复某个 session 的历史，并支持分页。

### `renameSession(...)`

作用：

只改 title，不该动 preview、scene、updatedAt 之外的东西。

### `clearSession(...)`

作用：

删掉这个 session 相关的所有 Redis key，并从索引里移除。

## 四、为什么要分 prompt-turns 和 archive-turns

这一步一定要真正理解。

### prompt-turns

给模型看的。

越短越好。

### archive-turns

给前端恢复聊天记录看的。

越完整越好。

如果不分开，就会出现：

- 你为了省 token 把历史裁短
- 前端聊天记录也跟着丢

这显然不合理。

## 五、`AiConversationMemoryAdvisor` 在做什么

它把 memory 注入 prompt 这件事收成了 advisor。

也就是说：

### memory service 负责

- 存
- 取
- 管 session

### memory advisor 负责

- 把取出来的 summary 和 recent turns 注入 prompt

这两个职责一定要分开记。

## 六、再看流式输出

`AiChatStreamChunk` 很简单，但你不能小看它。

它的四个字段分别是：

- `sessionId`
- `scene`
- `content`
- `done`

### 为什么要有前缀 chunk

因为前端一开始就需要知道：

- 当前 session 是哪个
- 当前 scene 是哪个

所以会先发一个空内容 chunk。

### 为什么最后还要发 done chunk

因为前端需要知道：

`现在真的结束了`

### 为什么 `doOnComplete(...)` 里要写入 memory

因为流式过程中答案是分段到达的。

但记忆里最好只存完整答案。

所以要等流结束再统一写。

## 本章小练习

你现在自己做一个极简实验：

1. 假设不用 Redis，只用内存 `Map`
2. 先写一个最小 `ensureSessionId`
3. 再写一个最小 `appendTurn`
4. 最后写一个最小 `streamChat`，在完成时把内容写进去

先把感觉建立起来。
