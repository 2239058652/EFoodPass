## 先说清楚

你现在最缺的不是“再看一遍代码”，而是：

`把代码里的每个角色拆开理解。`

比如你以前可能会说：

- 这个类是 AI service

但你现在应该开始练习这样说：

- 这个类是 HTTP 入口
- 这个类是总编排器
- 这个类是某个场景的处理器
- 这个 DTO 是给前端看的
- 这个 DTO 是给模型解析用的

这就是这套文档的目标。

## 每章怎么读

每章都按这个顺序：

1. 先看“本章目标”
2. 打开文中提到的文件
3. 一边看文档，一边看代码
4. 看完后做“小练习”
5. 最后做“自查问题”

## 这套文档里的固定格式

### 1. 我会先列“先看的文件”

你先只打开这些文件。

不要一章里把整个 `modules/ai` 全部点开。

### 2. 我会讲字段

比如我会写：

- `sessionId`：表示这轮聊天属于哪个会话
- `answerType`：表示这次回答是正常、受限、未找到还是降级

### 3. 我会讲方法

比如我会写：

- `chat(...)`：同步聊天主入口
- `streamChat(...)`：流式聊天主入口
- `buildPlan(...)`：某个场景返回 prompt 计划

### 4. 我会讲注解

比如我会解释：

- `@RestController`
- `@Service`
- `@Data`
- `@AllArgsConstructor`
- `@Valid`
- `@NotBlank`

## 你要避免的学习误区

### 误区 1：把注解当魔法

比如：

- `@Data` 不是魔法，它只是帮你生成 getter/setter
- `@RestController` 不是魔法，它本质上是让类变成 Web 接口控制器

### 误区 2：看到一个大类就想全懂

比如 `AiChatServiceImpl` 很大。

你不要试图第一遍就全懂。

正确做法是分块看：

- 先看 `chat(...)`
- 再看 `streamChat(...)`
- 再看 fallback
- 再看 retrieval

### 误区 3：只看“做了什么”，不问“为什么”

比如：

- 为什么 `scene` 不信任模型？
- 为什么 `toolStatus` 要单独存在？
- 为什么 prompt memory 和 archive history 要分开？

这些“为什么”才是你以后自己写得出来的关键。

## 本章小练习

现在只做一件事：

打开下面两个文件：

- `src/main/java/com/epass/food/modules/ai/controller/AiChatController.java`
- `src/main/java/com/epass/food/modules/ai/service/impl/AiChatServiceImpl.java`

然后自己写一句话：

- Controller 负责什么
- ServiceImpl 负责什么

你写不清，就继续看本章，别急着跳。
