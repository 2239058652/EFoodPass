## 一、先看 `AiChatController`

路径：

`src/main/java/com/epass/food/modules/ai/controller/AiChatController.java`

### 1. 类上的 `@RestController` 是什么

它表示：

`这个类是一个 Web 接口控制器，方法返回值会直接变成 HTTP 响应体。`

如果没有它，Spring MVC 不会把这个类当成接口控制器来用。

### 2. 类上的 `@RequestMapping("/ai/chat")` 是什么

它表示这个类下面所有接口，都挂在 `/ai/chat` 路径下面。

所以你看到的方法：

- `@PostMapping`
- `@GetMapping("/sessions")`
- `@PutMapping("/session/{sessionId}/title")`

它们最终都会拼到 `/ai/chat` 下面。

### 3. controller 里为什么只有一个字段

你会看到：

- `private final AiChatService aiChatService;`

这表示 controller 本身不做业务。

它只负责：

- 接参数
- 拿登录用户
- 调 service
- 返回统一响应

这是很标准的分层写法。

## 二、看 `chat(...)` 方法

### 方法签名里这几个参数分别是什么

#### `@Valid @RequestBody AiChatRequest request`

这两个东西要一起理解。

##### `@RequestBody`

表示：

`把 HTTP 请求体里的 JSON 反序列化成 AiChatRequest 对象。`

比如前端发：

```json
{
  "message": "订单 1 是什么状态？",
  "sessionId": "abc"
}
```

Spring 就会把它变成一个 `AiChatRequest`。

##### `@Valid`

表示：

`在真正执行方法前，先对 request 做参数校验。`

这个校验规则来自 `AiChatRequest` 里的注解。

#### `Authentication authentication`

这个对象不是你自己 new 的。

它来自 Spring Security。

它表示当前登录用户的认证信息。

controller 里会从它身上拿：

- 当前用户是谁
- 当前用户有哪些权限

### 方法内部为什么要转成 `LoginUser`

你会看到：

```java
LoginUser loginUser = (LoginUser) authentication.getPrincipal();
```

意思是：

`当前认证主体在这个项目里被约定成 LoginUser。`

它里面至少有：

- `userId`
- `username`
- `nickname`

这里最关键的是 `userId`，因为后面所有 session、订单权限、会话记忆都依赖它。

### `canViewAnyOrder` 是怎么来的

你会看到一段逻辑：

```java
boolean canViewAnyOrder = authentication.getAuthorities().stream()
        .anyMatch(authority -> "food:order:detail".equals(authority.getAuthority()));
```

它在做：

`检查当前用户是否具备后台级订单详情权限。`

这很重要，因为 AI 不能绕过你原来的权限系统。

### 最后为什么返回 `Result.success(...)`

这是你项目统一响应格式。

所以 AI 接口不会直接裸返回 `AiChatResponse`，而是统一包装成：

```json
{
  "code": 200,
  "message": "success",
  "data": { ... }
}
```

## 三、看 `AiChatRequest`

路径：

`src/main/java/com/epass/food/modules/ai/dto/AiChatRequest.java`

### 字段 1：`message`

这是用户这一轮说的话。

### 上面的 `@NotBlank`

表示：

`message 不能为空，也不能只是空格。`

比如：

- `""` 不行
- `"   "` 也不行

这就是为什么 controller 层可以在业务逻辑开始前就把脏请求挡住。

### 字段 2：`sessionId`

表示这一轮请求属于哪个会话。

它为什么没有 `@NotBlank`？

因为新会话第一次发消息时，前端可以不传，后端会自己生成。

## 四、看 `AiChatResponse`

路径：

`src/main/java/com/epass/food/modules/ai/dto/AiChatResponse.java`

这个类是你现在 AI 响应结构的核心。

下面逐个解释字段。

### 1. `sessionId`

表示这一轮回答归属于哪个会话。

为什么要回给前端？

因为前端下一轮还要继续带回来。

### 2. `content`

这是用户真正看到的回答正文。

这是最像“传统聊天”的字段。

### 3. `scene`

表示这次问题属于哪个业务场景。

比如：

- `order`
- `item`
- `system`

它的主要用途是：

- 前端决定显示什么风格
- 后端调试时知道场景路由结果

### 4. `grounded`

表示这次回答是不是基于系统提供的真实事实或真实限制得出的。

这不是“模型自信不自信”，而是系统层面的可信标记。

### 5. `nextAction`

表示前端下一步适合做什么。

例如：

- `view_order_detail`
- `view_order_module`
- `ask_more_details`

这不是模型随便说的，而是系统控制字段。

### 6. `answerType`

表示这次回答属于哪一种业务状态。

例如：

- `normal`
- `not_found`
- `restricted`
- `degraded`

这个字段对前端很重要，因为前端可以根据它决定展示样式。

### 7. `toolStatus`

表示如果本轮用了工具，工具结果是什么。

例如：

- `success`
- `not_found`
- `restricted`
- `degraded`
- `none`

### 8. `card`

这是给前端的结构化展示卡片。

也就是说，你这个 AI 接口不只是返回一句话，还能返回一个可展示的小结构体。

### 9. `usage`

这是模型侧元数据。

比如：

- 用了哪个模型
- prompt token 多少
- completion token 多少

### 10. `conversation`

这是当前会话应用情况的元数据。

比如：

- 这轮有没有用历史
- 有没有用摘要
- 有没有复用上一轮 scene

### 11. `retrieval`

这是 RAG 检索元数据。

比如：

- 有没有检索
- 检索命中了几条
- knowledgeBase 是什么
- filterExpression 是什么

---

## 五、看 `AiChatStreamChunk`

它是流式接口一小段一小段返回的数据结构。

字段很少，但很关键：

### `sessionId`

告诉前端这段流属于哪个会话。

### `scene`

告诉前端当前流属于哪个业务场景。

### `content`

当前这一小段增量文本。

### `done`

表示流是否结束。

这让前端知道什么时候停止 loading。

---

## 六、看 `AiConversationSessionRenameRequest`

这个 DTO 很简单，但很典型。

它只有一个字段：

- `title`

并且有：

- `@NotBlank`

这说明：

`会话重命名也走正常 DTO + 校验链，而不是直接 Controller 里随便收一个字符串。`

这是比较规范的接口写法。
